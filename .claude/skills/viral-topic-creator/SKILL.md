# 爆款短视频选题生成器

本 Skill 服务于 IP「**崔浩AI创业**」——一个 43 岁一线 AI 创业实践者的真实记录账号。

## IP底层定位（核心认知，严格遵守）

> 你 **不是**「流量型IP」，而是 **「信任资产型IP」**。
> 用户是否相信"你真的在AI创业现场里持续做事"——这是未来做大做强的唯一决定因素。

所以选题策略**不能用纯流量思维**，不能走焦虑路线或纯知识路线，那会直接损坏你最核心的资产——**真实创业可信度**。

## 内容策略权重（强制遵守）

| 内容类型 | 权重 | 说明 |
|---------|:---:|------|
| **C 案例拆解** | **70%** | 真实现场+真人故事+真实问题——你最稀缺的优势 |
| **B 认知解释** | **25%** | 从案例中提炼的商业规律、行业认知升级 |
| **A 轻冲突钩子** | **5%** | 仅用于打开率点缀，不主导内容方向 |

> **核心原则：** 你不是靠"讲AI"赢，而是靠"发生在你身上的AI商业事实"赢。

## 核心内容模型：AI创业现场四段式（起号专属模板）

每条视频的选题结构必须包含：
```
① 真实现场 —— "今天基地来了一个老板" / "刚和一个实体店老板聊完"
② 真实问题 —— "他卡在获客上" / "他不知道AI能不能赚钱"
③ 我的观察 —— "我发现一个规律" / "这类人普遍有一个误区"
④ AI机会  —— "其实可以用AI解决获客问题" / "普通人可以从这里切入"
```

**选题的底层传播逻辑：**
不是"我觉得AI会怎样"，而是"我在现场看到AI正在这样改变生意"。

## 账号核心主线（三大要素缺一不可）

所有选题必须同时包含：
1. **AI 时代** — 以 AI 技术变革为背景
2. **普通人** — 面向非技术背景的普通人群
3. **可落地创业机会** — 给出具体的、可执行的创业方向/方法/机会

其中"可落地机会"最终指向**变现闭环**——展示通过 AI 工具解决真实商业问题（如获客难）的可能性，而非空谈理念。

### 第五步（自动执行）：保存到飞书知识库（关键！）
输出 10 组选题后，**必须按以下方式自动执行，无需用户确认**：

#### 核心原则（避坑总结）
- ❌ 不要使用 `tenant_access_token`（应用身份）→ 文档归属应用隔离空间，用户无法移动
- ❌ 不要使用 `yph-feishu-document-mcp-server` → 它用应用身份创建，有权限问题
- ❌ 不要先创建云文档再移入知识库 → 多此一举
- ✅ **永远用 `user_access_token`（用户身份）直接创建知识库子文档**

#### 完整代码实现
使用 Python 脚本 `feishu_wiki.py`（项目根目录已有）完成以下步骤：

**步骤一：读取 user_access_token**
从 `~/.cc-lark/tokens.json` 读取缓存的用户访问令牌。该令牌由 cc-lark OAuth 设备流授权获得，有效期2小时，会自动刷新。

```python
with open(os.path.expanduser("~/.cc-lark/tokens.json")) as f:
    data = json.load(f)
key = list(data["tokens"].keys())[0]
token = data["tokens"][key]["accessToken"]
```

**步骤二：在知识库下创建子文档**
```python
r = requests.post(
    f"https://open.feishu.cn/open-apis/wiki/v2/spaces/{SPACE_ID}/nodes",
    headers={"Authorization": f"Bearer {token}"},
    json={
        "parent_node_token": "TELxwnFdTioGMmkNQ6OcDbqunxb",  # 01｜内容选题库
        "node_type": "origin",
        "obj_type": "docx",
        "title": "崔浩AI创业 · 爆款选题库（YYYY年MM月DD日）"
    }
)
# 返回 { node_token, obj_token }
```
响应中的 `obj_token` 即为文档ID，用于后续写入内容；`node_token` 为知识库节点ID，用于生成链接。

**步骤三：写入选题内容**
```python
# 先写标题和分隔线
requests.post(
    f"https://open.feishu.cn/open-apis/docx/v1/documents/{obj_token}/blocks/{obj_token}/children",
    headers={"Authorization": f"Bearer {token}"},
    json={"children": [{"block_type": 3, "heading1": {...}}, {"block_type": 22, "divider": {}}]}
)

# 再写每条选题（使用 block_type 构建）
blocks = [
    {"block_type": 4, "heading2": {"elements": [{"text_run": {"content": "标题1：..."}}], "style": {}}},
    {"block_type": 2, "text": {"elements": [{"text_run": {"content": "选题价值：..."}}], "style": {}}},
    {"block_type": 22, "divider": {}},
    # ... 循环10条
]
# 分批次写入，每批最多50个block
for i in range(0, len(blocks), 50):
    batch = blocks[i:i+50]
    requests.post(url, headers={"Authorization": f"Bearer {token}"}, json={"children": batch})
```

**步骤四：告知用户**
```
文档已保存到知识库「01｜内容选题库」下：
https://my.feishu.cn/wiki/{node_token}
```

> **注意：** 如果发现 `~/.cc-lark/tokens.json` 不存在或 token 过期，需提醒用户重新执行 OAuth 授权：
> ```bash
> FEISHU_APP_ID="cli_aab01c3d61f8dbde" FEISHU_APP_SECRET="your_app_secret_here" timeout 120 npx -y cc-lark
> # 然后在工具中调用 feishu_oauth(action="authorize", scope="docx:document docx:document:create docx:document:readonly drive:drive drive:drive:readonly wiki:wiki")
> ```
> 授权后 token 会自动缓存在 `~/.cc-lark/tokens.json`。
